# 任务书

将方括号中的内容换成实际信息。GitHub 上的记录作为交接依据。

## 开发

```text
读 AGENTS.md 和 PROJECT.md。你负责开发 [Issue 链接]，风险为 [等级与原因]。
实现 [目标]，修改范围 [模块或目录]，满足 [验收标准]。
运行 [检查命令]。提交关联 PR，按下方「开发回执」记录变更、验证结果和遗留限制。
```

## 审查

```text
读 AGENTS.md 和 PROJECT.md。独立审查 [PR 链接] 的 [提交 SHA]，关联 [Issue 链接]。
自行核对差异、验收标准、CI 及 [风险重点]。在 PR 按下方「审查回执」记录证据和结论。
```

## 开发回执

开发 Agent 在 PR 记录，并返回同样的信息供负责人复制到 Issue 会话。

```text
Issue / PR：[链接]
当前 head：[完整 SHA]
完成的验收项：[行为、实现位置或证据]
检查：[命令或 CI 链接、结果；标明未跑项]
遗留项：[阻塞、风险或需要负责人操作的事；无则填无]
```

## 审查回执

独立审查 Agent 在 PR 记录，并返回同样的信息。

```text
Issue / PR：[链接]
审查者：[Agent 和模型]；被审 head：[完整 SHA]
核对项与证据：[验收、差异、CI 和独立验证结果]
发现：[阻塞或建议、位置、原因及需要如何验证；无则填无]
结论：[通过 / 返工 / 待补证据]
```

## 返工

```text
处理 [Issue 链接] 与 [PR 链接] 在 [被审 SHA] 上的必修问题：[发现与证据]。
完成 [预期结果]，运行 [回归检查]，更新原 PR，返回开发回执与新的 head SHA 供独立复审。
```

## 合并

```text
读 AGENTS.md 和 PROJECT.md。按 [授权记录] 将 [PR 链接] 的 [提交 SHA] 合入 [目标分支]。
核对合并顺序、当前提交的审查和 CI。发现冲突、提交变更或缺少授权时，在 PR 报告并交回编排者。
记录合并提交和 [Issue 链接] 的后续验收事项。
```
## 继续合并下一个（同一 Integrator）

```text
继续担任本轮 Integrator，查看 GitHub 当前开放 PR，按依赖与交付优先级选择下一个已通过独立审查、CI 且在现有授权范围内的 PR。基于最新目标分支和当前 head SHA 重新核验后普通 merge，记录结果并更新关联 Issue。若冲突、审查失效或授权不足则暂停并报告；高风险必须单独授权。不需要维护集中队列。
```
